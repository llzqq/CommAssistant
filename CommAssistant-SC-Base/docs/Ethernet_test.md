# Ethernet 测试步骤

目标：确认两台 Windows 电脑之间能正常收发 `HELLO` / `ACK`。

## 1. 打开软件
- 两台电脑都启动 `Comm Assistant`。
- 两台电脑都选 `Ethernet` 模式。

## 2. 填参数

### 服务器电脑
- `Protocol`：`TCP`
- `Role`：`Server`
- `Local IP`：`0.0.0.0`
- `Local Port`：`5000`
- `Remote IP`：空着或保持默认
- `Remote Port`：空着或保持默认

### 客户端电脑
- `Protocol`：`TCP`
- `Role`：`Client`
- `Local IP`：`0.0.0.0`
- `Local Port`：默认即可
- `Remote IP`：填服务器电脑的 IPv4
- `Remote Port`：`5000`

## 3. 点 Apply
- 先点服务器电脑的 `Apply`。
- 再点客户端电脑的 `Apply`。
- 服务器应显示已监听，客户端应显示已连接。

## 4. 点 Start Test
- 先在客户端点 `Start Test`。
- 客户端会发送 `HELLO`。
- 服务器收到后会显示 `HELLO`，并回 `ACK`。
- 客户端收到 `ACK` 后会显示 `Handshake success`。

## 5. 怎么算成功
- 客户端日志里能看到 `TX HELLO` 和 `ACK`。
- 服务器日志里能看到收到 `HELLO`。
- 两边状态都不再是错误或超时。

## 6. 联通后如何收发消息

当前 `Comm Assistant` 的 Ethernet 测试分两层：
- 第一层：`Start Test` 用于验证 TCP 链路和 `HELLO -> ACK` 握手。
- 第二层：握手成功后，用主界面的大发送框和接收区做实际消息收发。

### 客户端发，服务器收
- 保持客户端和服务器都已经 `Apply` 成功。
- 先在客户端点 `Start Test`，确认客户端显示 `Handshake success`。
- 回到主界面，在客户端的大发送框输入要发送的内容，例如：`hello from client`
- 发送格式选 `utf8`。
- 点击主界面的发送按钮。

预期现象：
- 客户端主界面发送历史里新增一条发送记录。
- 客户端 `Comm Assistant` 日志区能看到一条 `TCP TX ...`。
- 服务器 `Comm Assistant` 日志区能看到一条 `TCP RX ...`。
- 服务器主界面接收区能看到客户端发来的内容。

### 服务器发，客户端收
- 不需要重新建链，保持当前 TCP 连接即可。
- 在服务器主界面的大发送框输入内容，例如：`hello from server`
- 发送格式选 `utf8`。
- 点击主界面的发送按钮。

预期现象：
- 服务器主界面发送历史里新增一条发送记录。
- 服务器 `Comm Assistant` 日志区能看到一条 `TCP TX ...`。
- 客户端 `Comm Assistant` 日志区能看到一条 `TCP RX ...`。
- 客户端主界面接收区能看到服务器发来的内容。

## 7. 收发时看哪里

### 看发送是否真的走了 Ethernet 链路
- 不是只看主界面是否点了发送。
- 要同时看发送方 `Comm Assistant` 日志区里是否出现 `TCP TX ...`。

### 看接收是否真的回灌到了主界面
- 不是只看 `Comm Assistant` 收到了数据。
- 要同时看接收方主界面接收区是否出现相同内容。

### 看握手和业务消息的区别
- `Start Test` 产生的是 `HELLO` 和 `ACK`，用于确认链路可用。
- 主界面大发送框发出的才是实际业务消息。
- 只看到 `HELLO/ACK` 不代表主界面发送路径一定已经验证完成，还要再做一次双向业务消息收发。

## 8. 推荐测试顺序

1. 服务器 `Apply`
2. 客户端 `Apply`
3. 客户端 `Start Test`
4. 客户端主界面发送一条消息，检查服务器主界面是否收到
5. 服务器主界面发送一条消息，检查客户端主界面是否收到

如果以上 5 步都通过，可以认为当前 TCP 客户端/服务端收发链路已经打通。

## 9. 如果失败
- 检查两台电脑是否在同一个局域网。
- 检查服务器 `Local Port` 和客户端 `Remote Port` 是否一致。
- 检查客户端 `Remote IP` 是否填了服务器电脑的 IPv4。
- 检查防火墙是否拦截了端口 `5000`。
- 如果 `Start Test` 成功，但主界面收不到业务消息，优先检查是否确实使用了主界面的发送按钮和大发送框，而不是只在 `Comm Assistant` 里观察握手日志。
- 如果一端日志里有 `TCP RX ...`，但主界面接收区没有显示，说明应继续排查主界面回灌链路，而不是网络链路本身。
